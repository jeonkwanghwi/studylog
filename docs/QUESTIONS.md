## 2. 앱스토어 가격 티어 확인 필요

상품표가 이 가격을 전제한다. **스토어에 없는 티어면 가격이 아니라 하루 배팅액을 조정**해야 한다
(참가비 = 일수 × 배팅액이 깨지면 "낸 만큼 돌려받는다"는 약속이 깨진다).

```
7,000  14,000  21,000  28,000  30,000  42,000
```

특히 **21,000 / 42,000** 이 한국 티어에 있는지 확인해달라. 없으면 하루 3,000원을
2,900원 같은 값으로 내려서 맞춘다.

## 2.5 소셜 로그인 — 카카오 추가함

애플·카카오만 하려 했다고 해서 확인해보니, **구글은 이미 되어 있었다** (애플과 같은
OIDC라 코드가 12줄 차이). 빼지 않고 셋 다 둔다.

**카카오를 서버에 추가했다.** `kauth.kakao.com` JWKS 로 검증하고, audience 는
Kakao Developers 의 **REST API 키**다. 앱에서는 네이티브 SDK 없이
`expo-auth-session` 브라우저 플로우로 받을 계획이라 Expo Go 에서 바로 테스트된다.

필요한 것: Kakao Developers 앱 등록 → REST API 키, 그리고 리다이렉트 URI 등록.

## 2.6 EAS 프로젝트 — 푸시가 이것 없이는 동작 안 함

`expo-notifications` 의 `getExpoPushTokenAsync()` 는 `app.json` 에 EAS `projectId`
가 있어야 토큰을 준다. 지금은 없어서 `registerPushToken()` 이 항상 `false` 를
돌려준다 (던지지는 않으므로 앱은 정상 동작).

즉 **알림 5종이 서버에는 다 구현돼 있는데 기기로 갈 수단이 없는 상태**다.
`eas init` 한 번이면 되고, Expo 계정만 있으면 무료다.

## 2.7 카카오 로그인 버튼 — **제출 차단 사유**

처음엔 "확인 필요"로 적었는데 최종 리뷰어가 분류를 올렸고 그게 맞다.
**카카오 로그인 가이드라인은 버튼의 색·로고·문구를 의무화한다.** 지금은 우리
디자인 토큰으로 그려놔서 (브랜드 색을 토큰 체계에 섞고 싶지 않았다) 위반 상태다.

제출 전에 반드시 카카오 공식 버튼 에셋으로 교체해야 한다. 디자인 시스템의
일관성보다 이쪽이 우선이다 — 우리 취향 문제가 아니라 남의 브랜드 규정이다.

## 4. AWS 배포 — 같이 하기로 한 것

준비는 다 됐다. `server/deploy/runbook.md` 에 절차가 있고, 필요한 건:
- Lightsail t4g.small + RDS db.t4g.micro + S3 (월 $15~25 예상)
- **배포 전 `alembic check` 필수** — 마이그레이션이 손으로 작성됐고 진짜 Postgres에서
  한 번도 안 돌았다
- **FOR UPDATE 동시성이 실제 Postgres에서 미검증** — SQLite에선 락이 no-op이라
  테스트로 증명이 안 된다. 배포 후 확인해야 할 유일한 항목

## 5. 결정했지만 되돌릴 수 있는 것 (참고)

레저에 근거와 "틀렸을 때 비용"까지 적어뒀다. 특히 이 셋은 제품 방향이라 이견 있으면 말해달라.

- **홈의 가장 큰 숫자를 "돌려받은 돈"이 아니라 "아직 못 받은 돈"으로** — 손실회피 프레임.
  앱을 여는 것 자체가 부담스러워질 위험은 있다
- **되산 날(복구)은 완주로 안 쳐서 완주 보너스를 못 받는다** — 챌린지 막바지 복구 매출이 준다
- **전패해도 첫 챌린지 상한(3만원)이 풀린다** — 상한이 막으려던 건 실력이 아니라 경험 부족이라고 봤다

## 6. 판정 실측 결과 (2026-09-11, gpt-4o-mini)

실제 사진 8장으로 돌려봤다. **공부/무관 6장 중 6장 정확**, 응답 1.5~2.8초.

| 사진 | 판정 | 확신 | 사유 |
|---|---|---|---|
| 책상 위 책 | 통과 | 0.80 | "책의 크기와 배열로 보아 공부 환경" |
| 노트북 코딩 | 통과 | 0.90 | "코드 작성 화면으로 보아 공부 환경" |
| 도서관 | 통과 | 0.85 | "책장이 있는 독서 공간" |
| 음식 | 거절 | 0.90 | "음식과 관련된 장면" |
| 풍경 | 거절 | 0.90 | "공부와 관련 없는 자연 풍경" |

**발견한 위험 — 레이트 리밋이 곧 무조건 통과다.**
테스트 중 429가 한 번 떴고, 관대 폴백이 작동해 그 사진은 확신 0.00으로 통과됐다.
설계대로지만 뒤집으면 **판정이 통째로 꺼지는 상황**이다. 유저가 몰리는 저녁 시간대에
이게 나면 그날 인증이 전부 공짜로 통과한다. 현재는 재시도 없이 바로 폴백한다.

→ 고칠 방향: 429·5xx 는 짧은 지수 백오프로 2~3회 재시도한 뒤에만 폴백. 타임아웃(10초)
   예산 안에서. 그래도 실패하면 통과시키는 원칙 자체는 유지한다 —
   AI 장애로 유저의 공부 시간이 사라지는 것이 더 나쁘다.
